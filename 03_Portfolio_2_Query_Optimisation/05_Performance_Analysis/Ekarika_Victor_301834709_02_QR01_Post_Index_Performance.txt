QR-01: Customer Order History
Post-Index Performance Benchmark

1. Experimental Setup

Database: cloudmart_db
DBMS: PostgreSQL 18.6
Query: QR-01 Customer Order History
Additional index: idx_customer_order_customer_id
Indexed column: customer_order.customer_id
Number of benchmark runs: 5

The query was executed five times using EXPLAIN
(ANALYZE, BUFFERS, TIMING OFF).

4. Execution Plan Findings

PostgreSQL continued to use a sequential scan on
customer_order with the filter customer_id = 1.

The newly created index idx_customer_order_customer_id
was not used by the query planner.

The existing uq_order_item_product index supported
the lookup of matching order items.

5. Interpretation

The post-index benchmark does not demonstrate a
performance improvement for QR-01 on the current dataset.

The customer_order table contains only four records.
A sequential scan can be more efficient than an index
scan when a table is very small.

The first run was substantially slower than subsequent
runs. This variation indicates that individual execution
times should not be interpreted in isolation.

6. Conclusion

The customer ID index was created successfully, but
the PostgreSQL query planner did not select it for QR-01.

The median execution time increased from 0.106 ms in
the baseline benchmark to 0.160 ms in the post-index
benchmark. This difference does not prove that the
index caused slower performance.

Further testing with a larger representative dataset
would be needed to evaluate the index's potential benefit.
